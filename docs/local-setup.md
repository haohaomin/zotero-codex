# 首次安装：只需 XPI

适用于 Zotero 10、Codex 本地客户端。Better Notes 是笔记协作的可选依赖（已验证 3.3.3）。无需安装 Node.js、Git、Python，无需下载源码或打开终端。

## 1. 安装插件

从 [最新 Release](https://github.com/renhao12356578/zotero-codex/releases/latest) 下载 `zotero-codex-版本号.xpi`。只下载这个文件即可，其他压缩包供插件自动安装使用。

Zotero → 工具 → 插件 → 齿轮 → 从文件安装插件，选择 XPI。若提示重启，重启 Zotero。

## 2. 等待组件自动准备

打开 Zotero → 设置 → Zotero MCP。插件启动后会检测系统、处理器和已有 Node.js。本机 Node 版本与实际服务运行检查都通过时，只下载不含 Node 的服务包；否则复用已安装的专用 Node，或自动下载完整运行包。所有下载均来自本项目对应版本的 GitHub Release。

界面显示下载进度、校验和安装状态。服务包包含 MCP 服务与 PDF 依赖；完整运行包额外包含独立 Node。插件不修改、升级或删除系统 Node，也不改变 PATH，不要求管理员权限。组件保存在 Zotero 配置目录下的 `zotero-codex-runtime`。首次需要网络；安装成功后再次启动直接检查、复用本地组件。设置会显示当前是“复用本机”还是“使用专用” Node，以及已验证的版本。

下载失败时检查网络，然后点击「重试」。关闭「自动准备运行组件」可停止后续启动时的自动准备；已开始的操作继续完成。可以随时手动准备。

支持复用 Node 22.13+（22.x）或 24 及以上稳定版本，并要求 CPU 架构匹配、PDF 原生依赖及服务自检通过。桌面启动时会补查 Homebrew、标准安装目录、nvm、Volta 和继承到的版本管理器路径，无需加载 shell 配置。

若不想复用本机 Node，可关闭「优先复用本机 Node.js」。已安装的专用 Node 保留作回退：之后 Zotero 启动、点击「准备组件」「重试」「重新检查组件」或「连接 Codex」时，都会重新检测。系统 Node 被移除或不再兼容时，在这些检查中自动选择其他兼容 Node 或专用环境，再更新托管配置；需要重启 Codex 生效。插件不会在 Zotero 关闭时监视系统变化。

## 3. 点击「连接 Codex」

按钮按「准备组件 → 连接 Codex」排列。组件尚未准备好时，先点击准备；失败后显示「重试」。准备完成后，连接按钮可用，准备按钮变为「重新检查组件」。操作期间两项按钮暂不可用，避免重复执行。

这个按钮会自动完成：

- 开启 Zotero 高级设置中的本地 API。
- 找到 Codex 用户配置（默认 `~/.codex/config.toml`，支持启动 Zotero 时继承的 `CODEX_HOME`）。
- 备份已有配置，再创建或更新本插件的 `zotero` 连接。
- 保留其他 MCP、模型设置，以及原 Zotero 连接的工具限制。

重启 Codex。Zotero 保持打开，在 Codex 发送“检查 Zotero 连接状态”。随后可在 Zotero 打开论文，选择文字或创建区域批注，再问“解释我刚选择的内容”。

只需首次点击连接。后续由 Codex 自动启动本地 MCP 进程，不需要手动启动服务。插件本身不调用 AI，不需要向插件填写 OpenAI API Key 或 Zotero 云端 Key。

## 升级与已有用户

更新 XPI 后，插件自动准备对应版本的组件。已由插件托管的 Codex 配置会随之更新，请重启 Codex。更新失败保留原包与配置；不会覆盖正在运行的程序。旧包暂时保留，以兼容尚未关闭的客户端。

以前手动部署源码的用户：点击一次「连接 Codex」即可迁移到托管组件。在新连接检查成功前请保留原来的源码部署。

## 常见问题

- **无法获取运行包 / 下载失败**：检查是否能访问 GitHub Release；点击重试。插件不会偷偷改用不明镜像。刚更新插件时，运行包可能尚未发布。
- **已准备但 Codex 仍没有工具**：点击「连接 Codex」后完全退出并重新打开 Codex。准备组件和配置客户端是两个状态，刷新按钮不负责启动服务。
- **已有其他同名 zotero 服务**：插件不会覆盖不同服务。先在 Codex 中重命名那一项，再连接。项目级配置若覆盖了用户级配置，需要在对应项目中调整。
- **Codex 配置语法错误 / 非标准内联写法**：不自动改坏文件，保留原样并提示；先修复设置。自动备份位于配置文件旁，文件名包含 `before-zotero`。
- **笔记协作不可用**：确认 Better Notes 已启用；部分操作需要打开笔记编辑器。
- **想连接其他客户端**：在「高级设置」点击「复制 MCP 配置」，将 `mcpServers` JSON 添加到目标客户端并重新加载 MCP。无需开启开发者模式；复制本身不会建立连接，格式以客户端要求为准。
- **想自行部署 / 离线部署**：参考 [开发者手动部署](manual-setup.md)。

连接文件 `zotero-codex-mcp.json` 含本机令牌，不要公开或移动；profile 是配置目录，通常不同于论文数据目录。设置里的「运行连接检查」只检查 Zotero 本地接口，不调用 AI，也不代表 Codex 已实际连接。「最近访问插件」也不是持续在线状态。

## 高级设置与开发者模式

「查看连接详情」只读显示运行环境、服务组件版本和自动管理的路径。Node.js 用来运行 MCP 服务脚本，由客户端启动，无需手动打开这些文件。

仅在调试自己的 MCP 服务、指定其他 Node.js 或使用自定义安装目录时开启「开发者模式：自定义导出路径」。路径只用于本次导出的配置，不会写入自动组件的设置，也不会修改已有 Codex 连接。关闭模式或重新打开设置后恢复自动路径。复制时检查文件存在性，不会运行或验证自定义服务；应用到目标客户端后应另行检查连接。

「打开连接文件所在目录」用于定位本地桥接连接文件、排查问题，通常不需要编辑。复制的配置不含令牌，但包含本机路径，不适合直接移到另一台电脑。

## 缓存与存储

设置 → Zotero MCP →「缓存与存储」中，点击「检查缓存」查看可清理的文件数量、大小和保留的组件占用；点击「清理缓存」会重新检查后执行，并报告实际释放的空间。无需重启 Zotero。

同一处的「自动清理缓存」开关默认关闭，支持设置清理阈值（0–102400 MB）与检查周期（1 天、7 天、1 个月，按 30 天计算），点击「保存规则」后生效。默认阈值 100 MB、周期 1 天。到期时只有**可安全清理的临时缓存**达到阈值才清理；已安装组件和近期文件不计入阈值。填 0 表示每个周期都执行清理，手动清理不受这些规则限制。

首次开启后稍后检查，此后按最近检查时间计算周期；低于阈值也会记录检查时间，避免重复扫描。修改规则后按最近检查时间重新判断是否到期。仅在 Zotero 运行期间执行，关闭期间错过的检查在下次启动后补做，不会重复执行多次。安装、连接或手动缓存操作期间自动延后。关闭开关不再安排后续清理，已开始的清理会完成。页面分别显示最近检查和实际自动清理时间，失败时显示提示。

仅清理插件运行目录下、超过 24 小时未修改的下载包残留、解压临时目录和 Node.js 检测／配置操作的临时结果。近期文件、包含符号链接或无法安全读取的目录会保留；安装、连接、检查和清理不能同时进行。部分文件删除失败时会提示，可稍后重试。

已安装组件（包括旧版本与备用 Node.js）可能仍被 Codex、Cursor 或自定义客户端引用，不作为缓存删除。连接文件、客户端配置及其备份、Zotero 论文、PDF、批注和 Better Notes 笔记均不在清理范围内。阅读选区快照保存在内存中，可用「阅读上下文 → 清除当前上下文」单独清除。

## 平台范围

提供 macOS Apple Silicon / Intel、Windows x64、Linux x64 / arm64 运行包。Windows arm64 原生 Zotero 暂不自动安装，界面会明确提示。真实 Zotero 安装流程在 macOS 验证；其他平台在 CI 验证运行包和服务依赖，图形宿主交互仍需进一步验收。
