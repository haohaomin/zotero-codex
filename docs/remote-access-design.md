# 远程访问技术方案

日期：2026-09-28。状态：设计阶段；尚未实现或部署。分支：`feature/remote-mcp-gateway`。

## 目标与范围

公网服务器提供远程 MCP 入口，本机主动建立出站连接，实际操作仍由本机 Zotero 和现有 MCP 服务执行。第一阶段面向单用户、单设备，允许多个经授权客户端连接。服务器不安装 Zotero、不同步整个文库；使用时电脑必须联网且 Zotero 运行。远程入口独立于现有本地 stdio 配置，远程关闭或故障不影响本地使用。

不要求本机公网 IP、入站端口或路由器映射。不使用远程 shell，不将 Zotero 本地 API 或本地访问令牌暴露到服务器。公网服务器是受信任的转发方：它能接触工具参数、论文正文和图片；第一版是两段 TLS，不宣称端到端加密。

## 结构与请求流程

```text
AI 客户端 -- HTTPS /mcp --> Caddy --> MCP 网关
                                        |
                                  已认证的 WSS 通道
                                        |
                      本地连接器（主动连接 /device）
                                        |
                               MCP Client / stdio
                                        |
                         现有 mcp/server.mjs
                                        |
                     Zotero 插件 / 本地 API / Better Notes
```

网关采用 Node.js 和现有 MCP SDK 的 Streamable HTTP 服务端；本地连接器使用 MCP SDK stdio 客户端启动已验证的本地 MCP 服务。WSS 仅承载经过校验的工具目录、工具调用、结果和控制消息，不提供任意 HTTP 代理、文件读取或命令执行。

本机上线后完成协议版本协商，握手本地 MCP 服务并注册允许的工具目录。客户端通过网关初始化、列出工具、调用工具。网关为调用分配唯一操作标识，附加客户端身份、会话、设备连接代次和超时时间；本机再次验证权限后执行，结果按原调用返回。文本及 MCP image 内容块保持原格式。

## 新增模块

- `remote/gateway.mjs`：Streamable HTTP、认证、客户端会话归属、设备注册和请求路由。
- `remote/agent.mjs`：本机 WSS 连接、stdio 子进程、心跳与重连、权限复核、操作状态。
- `remote/protocol.mjs`：版本化消息 schema、大小限制、请求/结果关联、错误代码。
- `remote/policy.mjs`：明确工具白名单与参数约束；网关和连接器均校验，未知工具默认拒绝。
- `remote/auth.mjs`：配对、设备凭证、客户端令牌、撤销与轮换。
- `deploy/remote/`：网关 Dockerfile、Compose、Caddy 配置示例和部署说明；镜像不包含 PDF 原生依赖。
- `addon/content/remote.js` 及设置页：启停连接器、远程状态、服务器地址、配对、权限与解绑。

现有工具与 PDF/笔记实现继续在 `mcp/`、Zotero 插件和 vendored adapter 中维护，不复制一套业务逻辑。自动运行组件包增加连接器及其依赖。连接器使用已验证的 Node 和托管服务路径；服务器不能指定要在电脑上执行的程序。

## 身份与授权

服务器只允许 HTTPS/WSS，反向代理终止 TLS，应用端口仅在 Docker 内网可达。工具调用默认无正文日志，凭证不放 URL。检查 Host；对带 Origin 的请求使用明确允许列表。配置会话数量、并发数、消息大小、速率和超时上限。

第一版采用可单独撤销的客户端 Bearer 令牌，适配允许配置 Authorization 请求头的客户端。不能据此声称兼容所有网页客户端；仅支持 OAuth 的客户端需后续添加符合 MCP 客户端要求的 OAuth 流程。

管理员通过服务器管理命令生成一次性配对码；短时有效、使用后失效并限制失败尝试次数。插件填写服务器地址与配对码后，获得高熵设备凭证。服务器保存设备及客户端令牌的校验值，设备凭证存入 Zotero/Gecko 凭证存储，不写普通偏好或诊断报告。客户端令牌与设备凭证分离，服务端会话必须绑定已认证客户端和指定设备。MCP Session ID 本身不能充当认证凭据。

工具权限由服务器允许范围与本机允许范围取交集。第一版默认远程只读；另提供明确开启的笔记编辑工具组。不能仅依赖上游 readOnlyHint，因为读取工具也可能打开编辑器或返回路径。

- 第一阶段允许文库元数据、检索、全文/PDF 按页读取、当前上下文/选区、批注、笔记内容和结构读取。
- 远程只读请求约束 `read_note(openEditor=false)` 等带副作用参数；输出内部路径时优先省略或明确其仅是本机路径。
- 编辑阶段允许已有笔记的指定编辑操作，保留 revision/requestID 校验；客户端还必须满足本机 Zotero 的实际权限。
- 第一版不开放原生授权、删除/清空回收站、按任意路径添加附件、外部文件同步配置等工具。其余现有工具逐一审计后加入白名单，不承诺远程提供全部 43 个工具。

## 生命周期和故障语义

默认关闭远程访问。启用后随 Zotero 启动连接器；关闭、解绑或退出时终止连接器及其拥有的 MCP 子进程。使用专用连接状态，与“桥接服务已就绪”区分；显示连接中、已连接、重连中、设备离线、认证失效等状态。Node 切换或组件升级后由插件重启连接器。服务器不能主动升级本机代码。

连接器使用心跳和有上限的指数退避加随机抖动重连，休眠恢复后重新注册。每次连接使用新代次，拒绝旧连接的迟到结果。断线不排队等待未来执行用户操作；只读调用明确失败后由客户端重试，写调用绝不自动重放。

网关的 MCP 会话独立于 WSS 连接，所有会话都有身份归属、空闲过期和数量限制。初版采用 stateful Streamable HTTP，不实现断线事件重放；网关重启后客户端重新初始化，不能用旧会话访问其他客户端的调用。取消是尽力而为，不宣称已撤销在 Zotero 中提交的写入。

写入启用前，在本机建立持久操作记录：操作标识、客户端、参数摘要及执行状态。发送前、开始执行、完成后分别记账，拒绝同标识不同参数。结果回传丢失或进程在提交前后崩溃时返回 `RESULT_UNKNOWN`，要求读回核对；不承诺 exactly-once。原插件内存中的 requestID 去重不能代替跨进程崩溃处理。操作记录默认不存笔记正文/图片，保留期和容量受限。

正常状态/检索采用较短调用期限；PDF 和图像采用较长但有限期限，并按工具配置，不能把所有调用统一为 30 秒。初始图像结果上限 32 MiB、请求上限 1 MiB，结合现有单图限制实测调整；超限返回明确错误，提示缩小页数或内容范围。连接器与网关都做背压及有界并发，写入串行化。

## 用户界面

设置新增“远程访问”：开关、服务器地址、配对码、连接状态、权限范围、重新连接、解绑、复制远程客户端配置。配对码和令牌输入与诊断信息隔离。默认复制仅包含公网 MCP 地址及认证填写说明，不复制设备凭证或本地连接令牌。

现有“连接 Codex”和“复制本地 MCP 配置”保持原用途。远程配置采用客户端所需 URL/认证格式，不沿用 stdio 的 command/args。

## 开发和测试顺序

1. **本地网关原型**：实现协议、网关、连接器及只读白名单；本地用三个进程模拟服务器、本机、远程 MCP 客户端。仅测试环境允许 loopback 明文地址，正式配置拒绝公网明文。
2. **只读闭环测试**：真实 MCP SDK 完成初始化、工具目录、状态、当前论文、文字选区、区域图片、PDF 页面、Better Notes 读取。测试数据使用隔离 Zotero profile，不修改日常文库。
3. **认证与故障测试**：错误/撤销/过期凭证、配对码重放、跨会话与跨代次请求、读权限越权、消息超限、并发、断网恢复、设备退出、服务器重启及子进程清理。
4. **笔记写入测试**：只在隔离笔记启用；验证 revision 冲突、去重、执行后回包丢失、执行中崩溃后的未知结果、取消后读回确认、不重放旧操作。
5. **插件集成与打包**：设置页配对/启停、凭证存储、自动启动、组件升级、关闭远程后本地 MCP 正常；macOS 真实宿主测试及五平台构建，其他平台的 GUI 验收另行标明。
6. **公网部署验收**：拿到服务器资料后部署 Docker/Caddy，验证域名/TLS、跨网络 WSS、客户端实际认证和工具调用、重启恢复、日志脱敏、令牌撤销和端口隔离。

在正式服务器验证之前仅交付开发分支、测试结果和部署模板，不宣称已支持真实公网访问。不自动替换日常安装或发布稳定版；先完成隔离测试，再根据实际客户端做部署验证。

Linux 发行版、CPU 架构、Docker 是否可用、域名及 DNS 控制方式、已有反向代理和 443 端口占用、希望接入的客户端。届时采用可用的 SSH 访问方式部署，凭证不提交到仓库。缺少这些资料不阻碍本地协议开发和隔离测试。
